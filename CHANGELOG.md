# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project
follows [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Changed

- **CI outlasts a slow Ubuntu mirror**: it installs packages with `scripts/apt-install.sh`, the same file as in every OxiGuitar repository. apt is stopped only when its downloads have not grown for 2 minutes, then tried again on the next mirror; while they grow, it may take as long as it needs (24 Nov 2026: fixed 5-minute tries failed jobs on mirrors at 80 to 185 kB/s).
- **The manual explains the ideas behind the plugin** (its overview, with pictures), shows how to use it with screenshots, says in Architecture and strategy what it can't do yet, what is left out on purpose and where help is wanted, and has a Credits page listing every project it uses, with links and thanks. The README has a plain-words introduction and a Credits section.

## [0.2.6] - 2026-11-22

### Added

- **Every test with one command** (mateusrdp/oxiguitar#273): `scripts/test-all.py` builds and runs all of this repository's tests, and tests the plugin against the newest OxiGuitar release, with a progress bar, a summary to paste into an issue and a log to diagnose from. The manual has a Features page naming the tests of every feature (CI checks it) and a Testing page.

### Changed

- **The manual is the plugin's own** (OxiGuitar #325): `docs/manual`, published at https://mateusrdp.github.io/oxiguitar-midi/. The no-sound-set advice and the Sound Sets dialog now link to the sound-set installer's manual instead of a page of OxiGuitar's.

## [0.2.5] - 2026-11-17

### Changed

- **The Sound Sets dialog** (#19): the sound sets are picked in the plugin's own dialog, **Plugins → MIDI Sound Sets…**, with **OK** and **Cancel**, where OxiGuitar's settings window (Tools → Plugins…, Settings…) used to be. A pick is kept only when you press OK, and the new sets load then, once: going down a list no longer saves and loads each entry on the way, so the lists no longer lag, close or jump to picks made seconds before. Cancel leaves the sets as they were. The dialog works with or without a song open, and while it plays. It lists the sets found when it opened, so each pick is answered at once.
- The `soundfonts` folder is asked for by its name (interface 1.8), as OxiGuitar no longer knows it (mateusrdp/oxiguitar#308).
- Plugin interface 1.9 (from mateusrdp/oxiguitar#306, the SDK at that commit until OxiGuitar's next release is tagged): OxiGuitar retired the settings window it drew for plugins. This version needs that release; older OxiGuitar versions refuse it.
- Dependabot leaves every `oxiguitar-*` crate alone (it proposed `oxiguitar-host` v0.13.1, which the tests do not build against); they move by hand with the interface.

## [0.2.4] - 2026-11-16

### Added

- **No sound set at all** (as in OxiGuitar's Flatpak until a set is added, #163): the footer says once, with a **Better sounds** link to the manual's page on the sound-set installer, where a set goes (the host's `soundfonts` folder, the Flatpak's own inside it). Playing still fails as before until a set is there.
- **Knowledge graph analysis** (Understand Anything): the `.ua/knowledge-graph.json` captures the project's architecture — 224 nodes, 332 edges across 10 layers and a 12-step guided tour — for navigation and documentation. Generated by the `/understand` command.

## [0.2.2] - 2026-11-04

### Changed

- **Sets with an `oxiguitar-set.json` are listed by a short name**: the source and the patch, such as `FreePats: Electric Guitar FSBS (clean)`, instead of `FreePats: Clean Guitar.sfz (installed, 1 MB, CC0 1.0, by FreePats (Electric Guitar FSBS, clean))`. The source is the file's `name`; the product and variant are the innermost parentheses of its `credit`, split at the first comma. The "Automatic:" row of each kind of track uses the same name.

### Added

- `oxiguitar-set.json` may name a `recommended` patch and give each patch of the set a name in `patches` (by path from the set's folder). A set with several patches plays only its recommended one where nothing is picked, and the others are listed by their names to pick; the sound-set installer writes both when asked to install every patch (oxiguitar-bettersounds-soundfonts after 0.1.2).

## [0.2.1] - 2026-11-04

### Changed

- **Better sounds are used as soon as they are installed.** A row of the settings window with no pick (and a track whose Sound is Automatic) now plays the best set whose `oxiguitar-set.json` names that row's role, as the sound-set installer's sets do: the clean, overdriven and distorted guitar sets, the bass and the drums play where nobody picked them. A set that names no role still plays only where picked, and a row nobody has a set for plays the best General MIDI set, as before. Each row's first entry now says what it plays ("Automatic: ..."). A pick still wins.
- **Acoustic guitars are two rows: Nylon-string guitars (General MIDI program 24) and Steel-string guitars (25).** Before, one row served both, so a recorded steel guitar played a nylon-string part. A pick made for Acoustic guitars (`acoustic-guitars` in the settings) still holds for both rows until each has its own, and a set whose `oxiguitar-set.json` says `"role": "acoustic-guitars"` stands for both; the new keys are `nylon-guitars` and `steel-guitars`. The track's Sound list has a "Like nylon-string guitars" and a "Like steel-string guitars" entry in place of "Like acoustic guitars" (a song saved with the old entry plays that track as Automatic).

## [0.2.0] - 2026-11-04

### Changed

- The advice that only basic sounds are installed, and the settings window, point to the sound-set installer (oxiguitar-bettersounds-soundfonts; `oxiguitar-install-sounds` on Linux), the manual's Better sounds page opening there.
- The `.deb` and `.rpm` suggest `oxiguitar-bettersounds-soundfonts`, the installer of the recommended recorded sound sets. The packages are made by oxiguitar-packages' release workflows now.
- The settings window's "Electric guitars" row is three: Clean guitars (General MIDI programs 26 jazz, 27 clean, 28 muted, 31 harmonics), Overdriven guitars (29) and Distorted guitars (30), so clean and distorted guitars in one song get sets of their own (mateusrdp/oxiguitar#152). The one electric pick of before (`electric-guitars` in settings.json) still holds for all three until each has its own; `oxiguitar-set.json`'s `role` takes `clean-guitars`, `overdriven-guitars` and `distorted-guitars`, and `electric-guitars` there stands for all three.

### Added

- The track dialog's section **Sound** (mateusrdp/oxiguitar#152): a track plays **Automatic** (the settings window's row its General MIDI program names; the default), **a row** of the settings window whatever its program says (a distorted guitar played clean into an amp model), or **a set**, exactly. Kept in the song's `.oxg` file. A set picked there that isn't on this computer plays as Automatic, and the footer says so once.

## [0.1.0] - 2026-11-02

First release in a repository of its own (mateusrdp/oxiguitar#165). The
plugin is the one of OxiGuitar 0.11.0, with its history: id
`oxiguitar.midi`, file `midi.oxp`, replacing `oxiguitar.soundfont`.

### Added

- Playing with SoundFont (2 and 3), DLS and SFZ sound sets; the settings
  window; sets in the user's, the system's and `/usr/share/oxiguitar/soundfonts`
  folders; `oxiguitar-set.json` metadata; the `no-sound-sets` advice (plugin
  interface 1.0 to 1.4).
- `build-oxp.sh`, a contract test that checks the built `.oxp` file through
  OxiGuitar's plugin host, and `tests/realtime.rs`, which plays an SFZ
  instrument through the real-time checks.
- `release.yml`: test builds, and on a `v*` tag a draft release with a zip
  per system, `.deb` and `.rpm` packages, a per-user Windows installer and a
  macOS `.pkg`.

### Changed

- The plugin SDK is a git dependency on the `v0.11.0` tag of
  mateusrdp/oxiguitar. The plugin sits at the repository's root.
- The listening packs use OxiGuitar's command line, Guitar Pro plugins and
  reference songs from the `v0.11.0` tag.
